# رسّام+ — المرحلة 1

## الإعداد (مرة واحدة)
1. Firebase Console ← Authentication ← Sign-in method: فعّل **Google** و**Email/Password** و**Anonymous**.
2. Authentication ← Settings ← Authorized domains: أضف دومين Vercel (مثل `your-app.vercel.app`).
3. Realtime Database ← Rules: الصق محتوى `database.rules.json` ثم Publish.
4. Realtime Database ← Data: انسخ رابط القاعدة. لو غير `https://sawe-317bb-default-rtdb.firebaseio.com` عدّل `databaseURL` في `index.html`.

## التشغيل محليًا
`npx serve .` (لا تفتح الملف بـ file:// لأن تسجيل Google لا يعمل هكذا).

## النشر على Vercel
ارفع المجلد إلى GitHub ← Vercel ← Import ← Framework: Other ← Deploy (لا يحتاج build).

## اختبار على موبايلين
1. موبايل A: ادخل كضيف ← أنشئ غرفة عامة. موبايل B (حساب مختلف): تظهر في "الغرف العامة" ← دخول.
2. ارسم من A: يظهر الخط عند B أثناء الرسم، ثم يثبت. جرّب تراجع ومسح (الأدمن فقط).
3. أنشئ غرفة خاصة ← زر "دعوة" ← افتح الرابط على B. جرّب نفس الرابط بدون الكود: يجب أن يُرفض.
4. دردشة من الطرفين، ثم رسائل سريعة متتالية: بعضها يُرفض (حد 0.7 ثانية).
5. الأدمن: كتم، ثم طرد لاعب. بعد الطرد لا يستطيع الدخول مجددًا.
6. اقفل التبويب ثم افتح الرابط: الرسم والمحادثة مستعادان من القاعدة.
7. اقطع الإنترنت: النقطة بجانب اسم الغرفة تصبح حمراء، وتعود خضراء عند الاتصال.

## حدود معروفة
- سعة الغرفة تُفحص من العميل فقط (قواعد RTDB لا تعدّ الأبناء).
- لا يوجد عدّاد لاعبين في قائمة الغرف العامة بعد.
- الكتابة أثناء انقطاع الإنترنت لا تُخزَّن محليًا بعد إغلاق الصفحة.

## المرحلة 2: لوحة الرسم الجديدة — اختبار على الموبايل
1. إصبع واحد يرسم. إصبعان يحرّكان ويكبّران اللوحة. أداة ✋ تحرّك بإصبع واحد.
2. كبّر ×10 وارسم: الخط يبقى حادًا (الرسم متجهي)، وعند الطرف الآخر يظهر في نفس المكان.
3. جرّب الماركر والممحاة والأشكال (خط/سهم/مربع/دائرة/مثلث) مع زر التعبئة، وتراجع/إعادة.
4. ⤢ يعرض الرسمة كلها، و1:1 يرجّع الحجم الطبيعي.
5. تصدير PNG شفاف أو بخلفية أو JPEG (يشمل كل الرسم وليس المنظر الحالي فقط).
6. الرسومات القديمة من المرحلة 1 تظهر كما هي. قواعد Firebase لم تتغير، لا حاجة لإعادة نشرها.

## المرحلة 3: الأفقي + الأشكال الجاهزة + التحديد
قواعد Firebase لم تتغير (لا حاجة لإعادة Publish).
1. ادخل غرفة: يحاول التطبيق تفعيل ملء الشاشة + الوضع الأفقي. لو المتصفح رفض يظهر شريط "تفعيل الأفقي". iPhone/Safari لا يدعم قفل الاتجاه، فلف الجهاز يدويًا.
2. 🧩 أشكال (في الشريط العلوي): اختر شكلًا، يظهر وسط اللوحة محددًا، حرّكه، كبّره بالنقطة السفلية، دوّره بالنقطة العلوية.
3. ⬚ تحديد: المس أي رسمة لتحديدها. لو لغيرك يظهر اسم صاحبها فقط، ولا يمكنك تعديلها.
4. تغيير اللون من منتقي اللون، و🎨 تعبئة، و┄ منقط تطبق على المحدد. نسخ وحذف من الشريط العائم.
5. ↩ ↪ تتراجع عن الرسم والأشكال والتحريك والتعديل والحذف.
6. ⛶ يخفي القوائم ويعرض اللوحة وحدها، وزر ⛶ نفسه يرجّعها.
7. 💧 التقاط: المس أي مكان لأخذ لونه.

## المرحلة 4: إصلاح الدخول + واجهة جديدة (مهم: القواعد تغيّرت!)
**يجب نشر `database.rules.json` الجديد كاملًا** (Realtime Database ← Rules ← الصق ← Publish). بدونه لن تعمل الأكواد القصيرة ولا عدّاد اللاعبين.

### ما الذي كان يسبب الخطأ
1. كان `catch` واحد يعرض نفس الرسالة لأي مشكلة (انقطاع، قواعد غير منشورة، غرفة محذوفة...).
2. فحص «الغرفة ممتلئة» كان يعدّ كل من دخل يومًا (members) وليس المتصلين الآن.
3. كان الدخول بالكود يقبل الرابط الكامل فقط.
4. ثغرة في القواعد: `code == secret` كانت تنجح عندما يكون الاثنان فارغين (تسمح بالكتابة في غرف غير موجودة).
5. غرف عامة قديمة تبقى في القائمة بلا حذف.

### الجديد
- رسائل منفصلة: لا اتصال / غرفة غير موجودة / خاصة تحتاج كود / كود خاطئ / ممنوع أو قواعد غير منشورة / ممتلئة، مع زر إعادة المحاولة وسطر «التفاصيل».
- كود دعوة من 8 أحرف (`invites/`) يُلصق في الرئيسية، ويقبل الرابط أيضًا.
- إنشاء الغرفة ذرّي: لو فشلت أي خطوة تُحذف الغرفة (لا غرف وهمية). صاحب الغرفة يحذفها بزر 🗑.
- عدّاد اللاعبين الحقيقي وحالة «نشطة/هادئة/ممتلئة».

### سيناريو الاختبار (موبايلين)
1. A: الرئيسية ← غرفة جديدة ← عامة ← إنشاء. تظهر نافذة النجاح بالكود.
2. B: تبويب «الغرف» ← تظهر بطاقة الغرفة بعدد 1/8 ← انضم الآن.
3. A: غرفة خاصة ← انسخ الكود وأرسله. B: الصق الكود في الرئيسية ← دخول.
4. B: جرّب كودًا خاطئًا: رسالة «الكود غير صحيح».
5. ارسما معًا وراقبا ظهور الخطوط عند الطرفين.
6. اخرجا وعودا: لا تتكرر غرف في القائمة، ويظهر الرسم المحفوظ.
